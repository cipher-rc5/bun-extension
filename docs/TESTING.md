# Testing

Use the Bun version selected in package.json and the workflows (1.4.3). Node.js is not required for project scripts.
The committed bunfig.toml selects Bun's runtime and shell for tools and their JavaScript children. `bun run check:bun`
rejects Node built-in imports/globals in first-party code and non-Bun package commands; lint includes this check.

```sh
bun install --frozen-lockfile
bun run type-check
bun run lint
bun run test
bun run build
bun run browser:install
bun run test:browser
bun audit
```

Unit tests cover message validation and compile-time response correlation, serialized counter writes, delayed
hydration, corrupt/overflowed counters, quota failures, bounded queues, trailing/coalesced analysis, alarm scheduling,
cleanup failures, literal/Unicode text matching, standards-compliant PNG compression, and release version rejection. The same strict TypeScript check
includes tests; Bun's execution alone does not check their types.

Browser fixtures use the actual popup bundle and helper source against native DOM. Chrome API mocks permit delayed
loads and rejected writes. A separate persistent Chromium context loads the actual MV3 extension and verifies
cross-surface messages, counter persistence over popup reload, URL-only pushState across isolated worlds, malformed
requests, and an actual service-worker stop/restart without resetting the cleanup alarm. Fixtures serve only explicit
routes on loopback. Browser failure traces are stored in test-results/ and retained by CI.

## Minimum browser version

The Chrome/Edge support floor is 111, matching the manifest and Tailwind v4 requirement. The fixture suite can run
against an explicit archived Chromium 111 executable, independently of the current Playwright browser:

```sh
COMPAT_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium-111 bun run test:compat
```

The official Playwright 1.31.2 browser metadata identifies Chromium 111.0.5563.19 as revision 1048.
Download an archive from Playwright's browser distribution and extract it completely before selecting its executable.
Both CI and release run this compatibility suite with the archived Linux browser.
`bun run browser:install:compat` downloads/extracts that browser and sets its path for subsequent CI steps.
For local macOS downloads, pass `mac` or `mac-arm64` and set the printed `COMPAT_CHROMIUM_EXECUTABLE` path when running the suite.
Compatibility mode runs native popup/DOM fixtures; the installed-extension and worker-restart test runs on current
Chromium. Repeat the minimum-version run when changing the emitted JavaScript, CSS tooling, or browser API usage.

## Performance guard

Run `bun run bench:text` for the repeatable word-count microbenchmark. It reports medians without imposing a
machine-dependent timing threshold; see [PERFORMANCE.md](PERFORMANCE.md) for fixtures and measured results.

The dense-highlight regression creates 1,000 matches, clears them, and asserts one normalization per parent with at
most 2,000 siblings visited. A nested-parent regression also verifies one normalization for a covered subtree. Unit
tests verify one text read per matching node, wide-tree rejection before child queuing, match budgets across text
nodes, and one ownership scan when cleanup finds no marks. These checks bound work independently of machine timing.
Word-count tests cover JavaScript's Unicode whitespace set and repeated large inputs. Matcher tests verify reuse and
recovery after budget failures.

Native browser tests use deterministic clocks to verify hidden-tab polling cancellation, trailing-route catch-up,
pagehide/pageshow, and disposal. Message tests verify that extra page-analysis fields are dropped before persistence.

## Release checks

```sh
bun run release:check v0.2.0
actionlint .github/workflows/ci.yml .github/workflows/release.yml
```

The unit suite rejects malformed, mismatched, and prerelease tags; stable release tags are vMAJOR.MINOR.PATCH.
GitHub OIDC attestations can only be generated by the tagged release workflow. Local checks validate the workflow
and package, but do not create a release or an attestation.
