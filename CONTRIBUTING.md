# Contributing

Use Bun for package installation, builds, and tests. First-party scripts use Bun APIs and Web APIs; do not add Node
built-in imports, Node globals, or node/npm/npx commands. bunfig.toml enforces Bun's runtime and shell, including
third-party CLI shebangs and browser-test workers. Keep direct dependencies exact and commit bun.lock updates with
their manifest changes. Use the packageManager toolchain version selected in package.json. `bun run lint` includes
the `check:bun` policy gate.

Run the checks in [docs/TESTING.md](docs/TESTING.md) before opening a pull request. Changes to asynchronous storage,
message boundaries, host DOM behavior, or lifecycle handling should include a regression covering the actual failure
mode. Native browser tests complement isolated helper tests.

For performance changes, keep representative fixtures and compare measurements using the same runtime, machine, and
build mode. `bun run bench:text` covers word counting; [docs/PERFORMANCE.md](docs/PERFORMANCE.md) describes its limits.
Prefer deterministic work bounds in regression tests over wall-clock assertions. Keep comments focused on invariants,
constraints, and non-obvious decisions; omit narration of code and headings that repeat nearby names.

The formatter covers project source, tests, configuration, workflows, and documentation. Local .agents tooling,
generated output, and archived review snapshots are excluded. Do not edit archived review evidence to satisfy lint.

The optional betterleaks pre-commit hook can be installed with bun install; the scanner is installed separately.
Report security issues privately using SECURITY.md.

For a stable release, update package.json and src/manifest.json to the same version, document user-visible changes
in CHANGELOG.md, run all gates, and push the matching vMAJOR.MINOR.PATCH tag. Release checksums, SBOM, and provenance
are generated by the workflow. Verify downloaded artifacts using the README commands.
